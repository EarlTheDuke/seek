## The answer to the one question that matters

**No. Nothing was killed, nothing was picked up, nothing was eaten, and the
chain breaks in two independent places — both of them proven, neither of them
guessed.**

**Break 1 — the word "branch" cannot reach the firewood.** `gather` learned to
carry its noun yesterday, and this run is the first to exercise it. The models
used it: 82 of 98 gather decisions named `branch`. Every one of them was
refused, because of the gate at `src/net/agent.js:2845`:

```js
const wood = want && !namesTheSame('wood', want) && !namesTheSame('branches', want)
  ? null : nearestDeadfall(...);
```

`namesTheSame` tests whether the *label* appears as a word inside what was
*said*. "branches" is not a word inside "branch", so the singular fails both
arms and `wood` becomes null. Deadfall is not in `snapshot.lo` either — it is a
pure function of the seed — so `nearestDrop('branch')` is null too, and the goal
falls straight through to `refuse(...)` and `roam()`. Run against the real
functions:

```
noun        n   resolveItemId()   gather gate sees deadfall?
branch      82   wood              NO
venison     14   venison           NO
arrow        1   arrow             NO
none         1   null              NO
```

The project already owns a resolver that gets this right, and `nouncheck` is
green over it: *"THE WORD A PERSON USES FINDS THE ITEM — "branch" is `wood` — 9
spellings, all found"*. `gather` does not call it. This is the project's
signature failure exactly as TRAJECTORY.md describes it — **a check green over a
path no caller could reach** — and it is a *regression introduced by the fix
that was meant to unblock arc 1*: before the noun landed, `want` was always `''`
and the empty string opens the gate, so every gather went to deadfall and
worked. Teaching `gather` to hear the noun is what stopped it finding wood.

**Break 2 — no mind in this world can eat.** `world.js:1599` honours
`intent.eat`; the limb is built. The only thing in the codebase that sets it is
the human keyboard (`src/player/input.js:341`, `i.eat = this.pressedEat`).
`goals.js` offers a mind fifteen verbs — wander, hunt, approach, avoid, hold,
gather, makeCamp, goTo, say, attack, offer, accept, give, follow, guard — and
**`eat` is not one of them.** A model-driven seat has no word for eating. Even
had break 1 never existed, and even had a seat filled its pack with venison, it
would have starved holding it.

So arc 1's blocker is not "the models are bad at surviving". They asked for the
right things, in the right order, for 110 minutes. Twice the world had no way to
say yes.

# What to fix next

Ranked by what unblocks arc 1 first. Every item has the evidence above it.

### 1. Route the gather noun through `resolveItemId` — arc 1 — size S
*Evidence:* 82 of 98 gather decisions named `branch`; the probe shows the gate
at `agent.js:2845` returns `wood = null` for every noun the models actually
used, while `resolveItemId('branch')` returns `wood` and `nouncheck` is green
over it.
*The fix:* resolve `want` to an item id once, then compare ids — deadfall when
the id is `wood`, `nearestDrop` by resolved id rather than by words. Falsy
resolution (`"none"`) should mean *anything lying about*, which is what the
mind meant. **Ships with an outcome test over a real socket: a seat told "pick
up branch" ends the test with wood in its pack.** Nothing counts until that
test says so.

### 2. Give a mind the word for eating — arc 1 — size M
*Evidence:* `world.js:1599` honours `intent.eat`; the only setter in the
codebase is a keypress at `input.js:341`; `goals.js` lists fifteen verbs and
`eat` is not among them. Meanwhile the minds spent the run reasoning explicitly
about hunger — *"starving, meat lies west"*, *"no food in pack"*.
*The fix:* an `eat` goal with an optional `item`, wired into the goal switch to
set the eat field, and named in the brief in `providers.js`. Outcome test: a
seat that starts hungry with venison in its pack ends the test less hungry.
*Do not merge 1 without 2* — fix 1 alone produces minds that can gather firewood
and still starve holding meat.

### 3. Make `refuse()` reach the log — arc 2 — size S
*Evidence:* ~98 refusals raised, 0 printed. *The fix:* route `refuse` through
`onLog` exactly as the speech gate's else-branch already is. This is a
prerequisite for verifying fix 1 from a run log rather than from a probe — with
it, this entire investigation would have been one line of output.

### 4. Print the tree the run is actually testing — arc 2 — size S
*Evidence:* three commits landed mid-run; the fleet executed code that was
fifteen minutes stale, and 953k tokens measured a tree that no longer exists.
*The fix:* the fleet banner prints the git SHA and whether the tree is dirty,
and repeats it in the final report. Loud warning on a dirty tree.

### 5. A measured run gets the server to itself — arc 2 — size S

### 6. Stop at the hour — arc 4 — size S
*Evidence:* one hour was asked for; the run went 2h30m and was still going when
